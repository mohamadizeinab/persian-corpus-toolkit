# روش‌های «صفحه بعد» اکستنشن — PCM-EXT-01/02/03/04 (v3.7/3.8/3.9)

اکستنشن «Persian Corpus Crawler» برای پیدا کردن صفحه بعدی ۴ روش دارد. روش انتخابی
به‌صورت یک string در فیلد `next_param` پروژه ذخیره می‌شود و `next_mode` همیشگی
`url_param` می‌ماند تا بدون هیچ تغییری در backend سازگار بماند (backend فقط
`url_param`/`none` را validate می‌کند).

| روش | مقدار `next_param` | مثال |
|---|---|---|
| پارامتر آدرس (قدیمی) | `item_index` | `?item_index=5` → `6` |
| لینک صفحه بعد | `next-link` یا `next-link:<css>` | کشف خودکار: `rel=next`، anchor با متن «بعدی/ادامه/Next»، در آخر anchorی که آدرسش «آخرین عدد مسیر +۱» باشد |
| عدد در آدرس (ساده) | `url-number` | `p_ghazal-001.html`→`002`، `p_ghazal-1.html`→`2`، `p_ghazal-495.html`→`496`، `sh495`→`sh496`، `sh1`→`sh2` |
| رجکس (دقیق) | `regex:p_ghazal-(\d+)\.html` | الگو روی مسیر آدرس خوانده می‌شود؛ باید **دقیقا یک** گروه `(\d+)` داشته باشد |

قواعد مشترک:
- «گام» (`next_step`) برای هر سه روش عددی (پارامتر/عدد/رجکس) کاربرد دارد.
- در روش‌های عددی، **صفرهای پیشین حفظ می‌شوند**: اگر عدد فعلی `001` باشد بعدی `002`،
  اگر `1` باشد بعدی `2`؛ عبور از عرض فعلی هم طبیعی است (`sh099`→`sh100`).
- در روش «عدد در آدرس»، آخرین توالی عدد مسیر انتخاب می‌شود (مثال
  `/book/2/page-15.html` → `16`). اگر عدد دیگری مد نظرت است، از رجکس استفاده کن.
- در روش «لینک صفحه بعد»، اگر بعد از آخرین صفحه لینک بعدی نبود، خواندن با پیام
  «خواندن تمام شد» متوقف می‌شود. اگر لینک روی صفحه‌ی خالی هم بود، به همان پیوسته.

## انتخاب روش (UI)
در پنل روی صفحه (پایینِ فهرست نقاط) select «روش صفحه بعد»:
- **پارامتر آدرس**: نام پارامتر query (مثل `item_index`).
- **لینک صفحه بعد**: اگر CSS لینک «بعدی» را می‌دانی بنویس (مثل `a[rel=next]`)؛
  خالی = کشف خودکار.
- **عدد در آدرس**: نیازی به ورودی ندارد.
- **رجکس**: الگو با یک گروه `(\d+)` (مثل `sh(\d+)` برای گنجور).

## نصب / آپدیت
1. `chrome://extensions`
2. **Developer mode** را روشن کن (بالا-راست).
3. روی کارت «Persian Corpus Crawler» آیکون **Reload (🔄)** را بزن.
   (برای نصب از اول: **Load unpacked** → پوشه `extension`.)
4. نسخه‌ی فعلی روی کارت باید **3.9** باشد (فیلد `version` در `manifest.json`).

## توقف مطمئن (v3.7)
مشکل قدیمی: «توقف» را می‌زدی، بعد از ~۱ ثانیه دوباره «در حال خواندن» برمی‌گشت.
علت: حلقه‌ی خواندن snapshot قدیمی‌اش را روی `pctRun` بازمی‌نوشت و `active:true`
بازطرح می‌شد؛ گزارش پایان دقیقه هم بی‌قیدوشرط `running` POST می‌کرد.

طراحی جدید (PCM-EXT-02):
- **token واحد حقیقت**: هر «شروع» یک `token` یکتا می‌سازد. «توقف» token را عوض
  می‌کند؛ از آن لحظه هیچ snapshot قدیمی نمی‌تواند run را زنده کند.
- **چک‌پوینت `isLive`** در هر نقطه‌ی حساس حلقه (بالای حلقه، بعد از بارگذاری،
  بعد از extract، قبل از ذخیره‌ی پیشرفت، و هر ثانیه‌ی استراحت) — اولین چکِ بعد از
  توقف، حلقه را می‌بندد.
- `endRun` فقط وقتی `active:false` می‌نویسد که token هنوز همان باشد (اثر side
  ندارد روی run جدید).
- **تب خواندن جدا**: خواندن روی یک تب `about:blank` پس‌زمینه انجام می‌شود؛ تب
  و پنل کاربر دست‌نخورده می‌ماند، پس وسطِ خواندن می‌توانی پروژهٔ دوم را باز کنی
  و رجکس/نقاطش را ویرایش کنی.
- **یک run در هر زمان**: اگر پروژه‌ای در حال خواندن باشد، «آزمایش و شروع» پروژهٔ
  دیگر می‌گوید «اول توقف را بزن»؛ دکمهٔ شروع پروژهٔ در حال خواندن «در حال
  خواندن…» می‌شود و panel توضیح می‌دهد.
- اگر تب خواندن بسته شود (کاربر/مرورگر)، run تمیز بسته می‌شود و `paused`
  گزارش می‌شود.
- اگر وسطِ خواندن توقف بزنی، وضعیت backend روی `paused` می‌ماند (گزارش
  «running» پایان دقیقه فقط وقتی token هنوز زنده باشد POST می‌شود).

## قفل cross-browser روی پروژه (v3.8 / PCM-EXT-03)

مشکل: وضعیت اجرای اکستنشن (`chrome.storage.local`) فقط داخل همان پروفایل
مرورگر دیده می‌شود؛ اگر **همان پروژه** در دو مرورگر/پروفایل اجرا شود، وضعیت
backend بین `running`/`paused` نوسان می‌کند و هر دو، cursor پیش می‌برند.
(پروژه‌های **متفاوت** همزمان امن هستند: ذخیره‌ی صفحه idempotent است و
API نوشتاری اکستنشن throttle ندارد.)

راه‌حل: backend تنها حقیقت cross-browser می‌شود — **اجاره‌ی run (lease) با TTL**:

- هر پروفایل مرورگر یک `owner` پایدار دارد (`pctOwner` در storage.local).
- «شروع» → `POST /api/projects/<id>/run` (claim): یک UPDATE شرطی اتمیک؛
  اگر قفل تازه و از آنِ owner دیگری باشد → **409** + پیام «این پروژه همین
  حالا توسط نشست دیگری در حال خواندن است».
- حین خواندن، هر صفحه **دو heartbeat** (`POST /run/heartbeat`) — حتی با
  سرعت کم صفحه/دقیقه، TTL نمی‌شکند. اگر heartbeat 409 بدهد (قفل دیگر مالک
  ما نیست)، run تمیز بسته می‌شود.
- «توقف»/پایان/بستن تب → `POST /run/release` (best-effort؛ اگر نرسد، TTL
  خودکار قفل را آزاد می‌کند).
- **TTL = 180 ثانیه (۳ دقیقه)**: اگر مرورگر بمیرد و release ندهد، قفل بعد از
  ۳ دقیقه خودکار منقضی می‌شود و نشست دیگری می‌تواند claim کند.
- اگر backend قدیمی باشد (route نباشد، 404)، اکستنشن با رفتار v3.7 محلی
  ادامه می‌دهد (فقط `console.warn`).
- پنل هر ۴ ثانیه پروژه را refresh می‌کند؛ اگر قفل تازه و از آنِ نشست دیگری
  باشد، دکمه «در حال خواندن (دستگاه دیگر)» می‌شود و شروع امتیاز داده نمی‌شود.
  (بررسی نهایی و قطعی، همان claim اتمیک سرور است.)

تست‌ها: `backend/test_run_lock.py` (14 تست RL-01..RL-14) + رگرسیون کامل.

## قواعد توقف خواندن (v3.9 / PCM-EXT-04)

سه قاعده‌ی مستقل، به این ترتیب در حلقه‌ی خواندن بررسی می‌شوند:

### ۱) حد عددی توقف (PCM-20.10 — قبلاً موجود)
باکس «حد عددی توقف (صفحهٔ آخر؛ خالی = بدون حد)» در پنل:
- **خالی** = بی‌نهایت، تا وقتی روش پیشروی دیگر صفحه‌ای ندهد.
- **پر** (مثلاً `500`) = خواندن دقیقاً تا آن شمارهٔ صفحه پیش می‌رود و قبل از
  باز کردن صفحه‌ی بعدِ حد، تمیز می‌ایستد (`paused` + پیام «به حد عددی رسید»).
- شماره‌ی صفحه از همان مقیاسی گرفته می‌شود که پیشروی آدرس از آن استفاده
  می‌کند (پارامتر query / عدد در آدرس / گروه رجکس)؛ با گام ۲، عبور از حد
  هم توقف می‌دهد.

### ۲) توقف بر مبنای تکرار محتوا (PCM-EXT-04 — جدید)
اگر **۱۰ صفحهٔ پشت‌سرهم محتوای یکسان** داشت (مثل صفحه‌ی قبلی‌ها، یا خالی/مشکوک
و عین هم)، خواندن تمیز می‌ایستد با پیام «ده صفحهٔ پشت‌سرهم محتوای یکسان … داشت».

- **مبنای تشخیص** با select «مبنای تشخیص تکرار محتوا» انتخاب می‌شود
  (`stop_field` در پروژه):
  - **خودکار (کل محتوا)** — مقدار همه‌ی فیلدهای استخراج‌شده، مرتب بر اساس نام،
    به‌هم چسبیده می‌شود.
  - **یک فیلد مشخص** — فقط مقدار همان فیلد (مثل `body`) معیار است؛ گزینه‌ها
    از نقاط (points) پروژه ساخته می‌شوند.
- امضا با هش 32-بیت djb2 ذخیره می‌شود؛ شمارش (`sameStreak`) در `pctRun`
  پایداری می‌کند، یعنی از دقیقه‌ای به دقیقه‌ی بعد ادامه دارد.
- فقط استخراج‌های **موفق** وارد شمارش می‌شوند؛ صفحه‌ای که متن نداشت قاعده‌ی
  جدا دارد: **۲ صفحهٔ خالی پشت‌سرهم** = توقف.

تست‌ها: `extension/test_next.js` (14 تست جدید امضا/حش/streak) +
`backend/test_projects.py` (SF-01..SF-08 برای `stop_field`، شامل مهاجرت
افزایشی) + رگرسیون کامل.
