## 4. What staging deliberately does NOT mirror

- No GPU model serving in the RAG path (vLLM models on s53 are other products' / shared; the staging chain answers through the synth-provider + staging litellm, no Neo4j/embedding dependency).
- No public DNS/certs (C4 owner-blocked) — access is by IP:port only.
- Keyfwd not containerized (C3-5) — accepted for the test vehicle; the containerized version is the production one.

## 5. Known staging defects carried from build (tracked, not hidden)

1. **C3-6 (HIGH)**: `radio2_api` (and prod `radio_api`) run on FILE bind-mounts of `api.py`/`rag_proxy.py` — same-size file rewrites are not picked up (inode pinning). Fix: directory mounts or bake files into the image.
2. **C3-5 (LOW)**: keyfwd bare process — no container supervision/restart.
3. **B3-U1**: `rag2-staging-core/secrets/` dir is 777 (key files themselves 600) — `chmod 700` pending.
4. **B3-U2**: inline keys in staging `litellm.yaml` — by design (test vehicle); the production fix removes this pattern entirely.
5. **B3-U5 context**: staging litellm binds 0.0.0.0:14101; `tyk-portal` unhealthy (other product).
