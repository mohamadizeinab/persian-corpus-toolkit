## 1. A1 — P6-1 / P6-1b firewall (owner action)

**Status: OPEN — owner action required.** This is the single root cause of every
RAG-path failure in the UI.

- Symptom: every public RAG chat (radio + portal) opens an SSE stream, waits exactly
  **120 s** (`RAG_TIMEOUT_S`), then returns
  `{"error":"timed out","code":"upstream_unreachable"}`.
- Root cause (6 proof points, all in
  `evidence/E6.3/security/e63-b2-p6-1b-public-rag-blocked.md`):
  1. UI containers use `RAG_LITELLM_URL=http://172.30.0.133:4101/v1` (the RAG
     LiteLLM `litellm-personal`, host-published 0.0.0.0:4101, 11 models).
  2. 42-port scan from s53: **only :4000 + :8000 open** — both belong to other
     products (learn-lite-llm, cms nginx); :4101/:8200/:8210/:4102 all DROP.
  3. :4000 rejects the RAG master key with `401 token_not_found_in_db` → not the
     RAG litellm.
  4. In-container probe: :4101 times out, :4000 answers in ms.
  5. s52 log window during public smokes: **no public RAG POST ever reached s52**.
  6. s52-local chain (same keys, same model rows) green ×3 → the failure is
     network, not service.
- **Pre-existing:** first observed T17 at 2026-11-16T16:53:35Z, before any B2 change.
  **Not a B2 regression.**
- Owner fix (exact): `ALLOW TCP 172.20.1.53 → 172.30.0.133:4101` (required),
  `:8200` (picker, recommended), `:8210` (direct gateway, recommended).
  No code change, no rollback concern.
