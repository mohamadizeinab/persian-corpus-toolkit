## 1. X-11 — LLM generation endpoint, resolved end-to-end

### 1.1 The chain (all legs proven live)

```
RAG gateway (s52, :8210)
  └─ GATEWAY_LLM_ENDPOINT=http://127.0.0.1:4101/v1/chat/completions   (model: qwen38-hub)
       └─ litellm-personal (s52, 0.0.0.0:4101 → container 4000)
            └─ model "qwen38-hub"  (STORE_MODEL_IN_DB=True; api_base ENCRYPTED with
               LITELLM_SALT_KEY in table "LiteLLM_ProxyModelTable", ciphertext len=38)
                 └─ vllm-qwen38 (s53) — Qwen3.8-27B-FP8, 0.0.0.0:8000, no --api-key
```

### 1.2 Evidence per leg

1. **litellm model list** (in-container python, master key never left the container): 11 models incl. `qwen38-hub`, `rag-mizan`, `rag-general`, `rag-fiqh`, `portal-rag-*`, embeddings. `/v1/models` does not expose `api_base`.
2. **`/model/info`** (admin, in-container): returned `api_base=None` for this image version — the field is not populated by the API; not an absence of config.
3. **Functional LLM probe (1 token, temperature 0):** `POST /v1/chat/completions` model=`qwen38-hub` → **HTTP 200 in 123 ms**, `usage={completion_tokens:1, prompt_tokens:53, total_tokens:54, reasoning_tokens:1}` — a real inference completed through the hub.
4. **Direct endpoint probe from s52 → s53:8000:**
   - `GET http://172.20.1.53:8000/v1/models` (no auth) → `model id: /models/Qwen3.8-27B-FP8`
   - `GET http://172.20.1.53:8000/health` → **200**
   - TCP s52→s53:8000 OPEN; prometheus on s52 already scrapes `vllm-qwen-53 http://172.20.1.53:8000/metrics` (UP).
5. **vllm-qwen38 container cmd:** `--model /models/Qwen3.8-27B-FP8 --max-model-len 200000 --gpu-memory-utilization 0.85 --kv-cache-dtype fp8 --host 0.0.0.0 --port 8000 --reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_coder` — **no `--api-key` flag** ⇒ the inference API is unauthenticated at the vLLM layer.

### 1.3 Findings

- **F-H5-1 (X-11 RESOLVED):** The LLM generation endpoint is **vLLM serving `/models/Qwen3.8-27B-FP8` on s53 at `http://172.20.1.53:8000` (OpenAI API, no API key)**, reached via litellm `qwen38-hub`. The exact encrypted `api_base` string was **not printed** (ciphertext stays in DB; salt stays in container; the image's decrypt helpers were not importable) — but all four functional probes converge on the same endpoint, which is dispositive.
- **F-H5-2 (security, HIGH):** The 27B inference API is **unauthenticated on 0.0.0.0:8000** on s53. The operator-box exposure sweep (§3) shows `s53:8000 OPEN` from a non-LAN-trusted vantage ⇒ anyone who can reach that IP:port can consume GPU inference (and read the model name). Recommend: bind to 127.0.0.1 + s52-only reverse path, or `--api-key` + firewall.
- **F-H5-3 (functional):** RAG chat chain is live locally on s52: model=`rag-mizan` chat → HTTP 200 in 29,336 ms with a real Persian answer. (Latency = LLM generation over the s53 hop; expected.)

### 2.2 Live state at audit time

- `127.0.0.1:8081` on s53: **no listener** (`ss -tln` empty; `curl` 000; no docker port mapping).
- Public hostname `strategies-dna-unexpected-riverside.trycloudflare.com`: **DNS resolution fails** from both the operator box (curl exit 6) and s53 (`getent` rc=2) — consistent with a **quick tunnel whose edge session is no longer alive** (quick-tunnel hostnames resolve only while a client holds a connection to the Cloudflare edge).

### 2.3 Findings

- **F-H5-4 (CLOUDFLARED = PUBLIC_EXPOSED by design):** The tunnel is a **Cloudflare quick tunnel (trycloudflare.com) with no access control** — no Access policy, no token at the ingress, 404 fallback. By design, whenever it is alive, it is a **public, unauthenticated URL** into `127.0.0.1:8081`.
- **F-H5-5 (currently inactive):** At audit time the ingress target (8081) has no listener and the hostname does not resolve ⇒ the tunnel is effectively dormant. **Dormant ≠ removed**: the container is running and will re-expose the URL on restart/reconnect. Recommend: remove or convert to a named tunnel with Access policy; if 8081 was a dev endpoint, document what it served (Jul 23, 2026).
- **F-H5-6 (config hygiene):** `config.yml`/`credentials.json` are root-owned 600 on a world-listable dir; `public-url.txt` is saber-readable (fine). Config audit required root-equivalent read via `docker cp` (no shell exec — the image has no `sh`).
