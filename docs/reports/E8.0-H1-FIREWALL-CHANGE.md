## 3. CHANGE PLAN

### 3.1 Root preflight (operator to run **before** approving, output pasted back)

These three are read-only and finalize the plan:

```bash
# 1) current DOCKER-USER chain (what docker inserted, anything else present)
sudo iptables -S DOCKER-USER

# 2) current UFW allow list (what is already opened, verbose)
sudo ufw status verbose

# 3) network mode of the two host-net candidates (decides rule form, §4.2)
sudo docker inspect rag-gateway rag-registry --format '{{.Name}} {{.HostConfig.NetworkMode}}'
```

**Decision rule for 3:**
- If `rag-gateway`/`rag-registry` report `NetworkMode: host` → their published sockets live on the host stack; s53→s52 packets to 8200/8210 traverse the **INPUT** chain (UFW-managed), **not** DOCKER-USER. In that case A-1 as a DOCKER-USER rule covers **only 4101**, and 8200/8210 additionally need UFW rules:
  ```bash
  sudo ufw allow from 172.20.1.53 to any port 8200 proto tcp
  sudo ufw allow from 172.20.1.53 to any port 8210 proto tcp
  ```
  (persisted automatically by UFW — no netfilter-persistent needed.)
- If either reports a bridge network with published ports → DOCKER-USER (FORWARD, pre-DNAT) covers all three and the single rule in §3.2 suffices.

Given `ss` shows `0.0.0.0:8200`/`0.0.0.0:8210` with **no** container publish in `docker ps` (no `->port` mapping for those two containers in `h1_s52_preflight.raw.txt` L43-55), the **host-net hypothesis is strongly indicated**; expect the UFW-allow branch. The A-1 package below therefore includes **both** parts as one atomic change set.

### 3.2 A-1 change set (the ONLY mutation, applied only after approval)

```bash
# Part 1 — docker-published port 4101 (FORWARD/DOCKER-USER, pre-DNAT):
sudo iptables -I DOCKER-USER -s 172.20.1.53 -p tcp -m multiport --dports 4101 -j ACCEPT

# Part 2 — host-net ports (INPUT/UFW), only if §3.1 step 3 confirms host mode:
sudo ufw allow from 172.20.1.53 to any port 8200 proto tcp comment 'E8.0-H1 A-1 s53 rag-registry'
sudo ufw allow from 172.20.1.53 to any port 8210 proto tcp comment 'E8.0-H1 A-1 s53 rag-gateway'
```

Properties:
- **Source-restricted** to the single known s53 address (172.20.1.53) — nothing else gains access.
- **Port-restricted** to exactly 4101/8200/8210. **4000, 4102, 5435 and all other ports untouched.**
- `INSERT` at the top of DOCKER-USER guarantees evaluation before docker's own rules; UFW appends in its managed section (order irrelevant for these isolated ports).
- **Never `iptables -F DOCKER-USER`** — that would destroy docker's runtime rules for every published port on the box.

### 3.3 Persistence (revised — the E8.0-G step is invalid on this host)

`netfilter-persistent` is **not installed**; `/etc/iptables` does not exist. Options, in recommended order:

1. **Recommended:** a systemd oneshot that re-applies only the Part-1 rule at boot (idempotent, guarded):
   ```ini
   # /etc/systemd/system/rag-s53-acl.service
   [Unit]
   Description=E8.0-H1 A-1: allow s53 (172.20.1.53) -> 4101 in DOCKER-USER
   After=network.target docker.service
   [Service]
   Type=oneshot
   RemainAfterExit=yes
   ExecStart=/bin/sh -c '! iptables -C DOCKER-USER -s 172.20.1.53 -p tcp -m multiport --dports 4101 -j ACCEPT 2>/dev/null || iptables -I DOCKER-USER -s 172.20.1.53 -p tcp -m multiport --dports 4101 -j ACCEPT'
   [Install]
   WantedBy=multi-user.target
   ```
   ```bash
   sudo systemctl daemon-reload && sudo systemctl enable --now rag-s53-acl
   ```
   (Part 2 needs no work: UFW persists its own rules in `/etc/ufw/user.rules`.)
2. **Alternative:** `sudo apt-get install iptables-persistent && sudo netfilter-persistent save` — installs a new package on a production host; acceptable if the operator prefers the standard tooling.

**Caveat (documented, not blocking):** the DOCKER-USER chain is (re)built by the Docker daemon; on a s52 reboot, docker starts before our oneshot re-inserts the rule. Between boot and oneshot execution, s53→4101 is momentarily blocked again — acceptable for this service (no time-critical consumers at boot).
